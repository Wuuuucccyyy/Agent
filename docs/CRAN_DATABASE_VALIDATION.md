## 协作与画像内容

1. 来源采集/解析：确定包版本、函数别名、签名、参数、来源和许可证。
2. 函数元数据 Agent：校验函数身份并保留官方接口，不由 LLM 猜测参数默认值。
3. 适用数据 Agent：生成中文适用文本、任务类型、输入/参数/预处理/假设/输出/失败条件及未知项。
4. 证据复核 Agent：程序先校验引用；第二轮 DeepSeek 对照原文检查语义，失败时反馈修正，最多两轮。
5. 数据库发布：版本化保存、隔离待复核画像、发布完整批次快照、生成检索文本并按需建立向量索引。

原文先切分为有编号的确定性片段，模型选择编号，程序回填原文与位置，避免模型重新抄写引文。每条语义结论仍为 LLM 推断；引用存在只证明可定位，不证明解读正确。检索文本由已验证的结构化画像生成，不能与画像单独漂移。

`SemanticProfile` 的 JSON Schema 已导出到 `schemas/SemanticProfile.json`。函数元数据同时保留 package、version、function_name、aliases、usage_rd、parameters、许可证、源码/Rd 哈希及文档路径。复合画像保留提取/复核尝试、质量状态、模型名与请求回执。

## 存储、恢复与检索实测

SQLite 包含 profiles、snapshots、builds、vectors。画像和快照按内容哈希版本化；构建出现错误时不切换当前活跃快照。JSON 恢复校验内容哈希、函数元数据、证据及检索文本一致性；恢复不需要网络或密钥。

真实 e5 模型为既定 revision 的 multilingual-e5-small。5 条可检索画像向量已持久化；再次访问全部复用，`encoded=0, reused=5`。按画像版本、检索文本哈希和模型名失效，恢复 JSON 后可重建向量。

见 [词法结果](../evaluation/results/cran_search_lexical.json) 和 [语义结果](../evaluation/results/cran_search_semantic.json)。这些是连通性/候选发现诊断，未进行独立标注，也未证明语义模型优于词法模型。
