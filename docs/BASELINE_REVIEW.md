# 基线第二轮复查

日期：2026-10-24。代码版本：0.1.1。范围为已有表格基线的正确性、可追溯性、运行效率与评估可信度；没有扩展数据源或将真实 LLM/Embedding 标为完成。

## 已修复的发现

| 优先级 | 触发情况与影响 | 修复 |
|---|---|---|
| P1 | 目标写“logistic regression/逻辑回归”时，原规则匹配“回归”，可能执行不符合请求的 OLS | 对识别到的未支持具体方法返回 needs_clarification；宽泛 task 参数也不覆盖具体方法冲突；单独“组间比较/降维”不强行确定 MANOVA/PCA |
| P1 | 解释变量恰好命名 intercept 时，原系数字典覆盖拟合截距 | 将拟合截距与预测变量系数分开存储，加入已知系数验证 |
| P2 | 选定变量不变，仅增加无关缺失列就改变查询中的 p 和缺失率，影响相似度 | 查询摘要只引用所选变量；测试要求整个排序结果保持一致 |
| P2 | 目标变量大量缺失时，残差自由度惩罚仍使用整表 n | 保存联合完整行数与该子集的解释变量秩，使用这些数值说明拟合限制；仍不自动删行 |
| P2 | 列名 a\|b 与分别缺失 a、b 得到同一缺失模式键；名为 <complete> 的列也会撞键 | 缺失列列表使用 JSON 编码，完整行是空列表，列名任意分隔符不再造成合并 |
| P2 | 原实现校验、解析、哈希分别读取文件；期间文件变化会导致统计数据与来源哈希不一致 | CSV/XLSX 校验、解析和 SHA256 使用同一份不可变字节快照 |

语义防护是有界关键词规则，不能理解任意否定、条件或复合研究需求；命中冲突时保守要求澄清。当前 OLS 对未指定具体回归类型的数值任务仍是有限基线，不构成完整方法选择系统。

## 效率改进与测量

- 知识库编码按编码器实例缓存一份候选文本及顺序；内容或顺序变化时失效。TF-IDF 词表与文档矩阵复用；SentenceEncoder 同样复用文档向量，查询仍每次编码。语义缓存只完成模拟接口测试。
- 同一个中心化矩阵不再先 SVD、再调用 matrix_rank 重算；秩使用已有奇异值及相同默认容差。联合完整行子集与原子集不同时才另行分解。
- 缺失模式按位压缩并聚合不同掩码，避免逐行创建 pandas Series 和拼接字符串。
- Markdown 数组仅预览 10 项，完整 JSON 不变；报告补齐软惩罚依据和官方来源，运行日志区分节点正常结束与分析被阻止。

复现：`python evaluation/benchmark.py`。数据和配置：seed=42，20000 行 × 12 列掩码，5 条知识画像，21 次重复词法查询，每项重复 5 次，报告中位数。结果位于 `evaluation/results/optimization.json`，测量前检查输出等价，缓存测量包含首次建库时间。

| 操作 | 修复前中位耗时 | 修复后中位耗时 | 本机倍率 |
|---|---:|---:|---:|
| 缺失模式统计 | 0.4924 秒 | 0.01733 秒 | 28.4× |
| 同库 21 次词法查询 | 0.07676 秒 | 0.01129 秒 | 6.8× |

这些是 Windows/Python 3.11 的局部微基准，不代表总体流水线、API 延迟或真实 Embedding 提速。一次性查询不会获得同样的缓存收益。完整数值数组仍会写入 execution.json、run.json 和 SQLite，大数据结果的独立文件存储属于后续优化。

## 输出兼容性

验证：52 项本地测试、compileall、PCA/OLS CLI 示例通过，七例检索冒烟评估已重跑。所有已识别缺陷都有针对性回归覆盖；真实 Sentence Transformer 的语义能力仍未实测。

包版本为 0.1.1。由于缺失模式键和 OLS 系数结构发生变化，DataProfile、QualityProfile、RelationsProfile、ExecutionResult 的 Schema 标为 0.2.0，TaskProfile/KnowledgeProfile 不变。旧 JSON 留档不自动重写，读取方应依据 schema_version 分支；当前示例已重新生成。

- `quality.missing_patterns`：旧 `"x1|x2"` 改为 JSON 字符串键 `'["x1", "x2"]'`，无缺失为 `'[]'`。
- `execution.metrics.intercept`：拟合截距；`coefficients` 字典只含预测变量。
- `relations.complete_rows`：所选数值解释变量的完整有限行数；新增 `analysis_columns`、`analysis_complete_rows`、`analysis_predictor_rank` 描述所选全部角色变量的联合可用行。旧画像没有新字段时标为未知，不拿总 n 冒充有效样本量。
- `run.application_version` 标记实现版本；执行节点额外记录 outcome。

## 仍应优先改进

1. **统计方法选择的验证能力**：每任务仅一个候选，无法验证软惩罚是否改善任务内部排序。先增加同任务合理替代方案及不适用条件，建立独立审核标签、验证/测试划分，再校准权重。现有七例 A/B/C 只能证明检查路径。
2. **语义理解与真实检索**：关键词规则和 TF-IDF 无法覆盖复杂中文研究需求。需要固定模型版本、真实运行及成本/准确性评估，不能将模拟接口测试计为语义能力验收。
3. **统计诊断**：补充测量尺度、研究设计、残差与组内协方差诊断。缺失/独立性未知保持未知，数值校验不能替代推断假设。
4. **规模与运行状态**：大数组独立持久化、限制高基数画像、按需计算关系矩阵、失败时保存中间画像；目前每次运行的编码缓存不跨进程持久化，也不承诺并发共享同一实例。

R、图片/PDF、生成代码隔离环境及 DARE 对照继续按原阶段计划推进，当前不扩大范围。
