一、项目目标与总体架构

系统允许用户通过自然语言、CSV/Excel、图片、图表及 PDF 等方式提交研究需求和数据。系统理解任务、生成画像、检索合适的 R 函数或统计方法、执行分析代码，并验证结果。

核心定位：多 Agent 协作重点放在数据画像生成。检索、代码执行和报告生成不必全部设计成独立 Agent，可以先作为工具或确定性模块接入。

模块

主要职责

总控 Agent

解析需求、调度画像子系统、维护任务状态、连接后续流程

多 Agent 画像生成子系统

离线生成统计知识画像；在线生成用户任务画像与实际数据画像

检索模块

双编码器、向量归一化、余弦相似度、硬约束过滤、软约束惩罚和候选排序

统计执行模块

通过 R/Python 读取数据、执行统计计算、拟合模型、生成图表并保存日志

结果验证模块

检查代码执行、统计诊断、结果依据和最终结论



端到端流程

用户多模态输入 → 需求理解 → 多 Agent 画像生成 → 画像质量校验 → 双编码器语义检索 → 统计约束惩罚与候选排序 → R/Python 执行 → 结果验证 → 分析报告。

二、多 Agent 画像生成子系统

画像生成分为两条工作流：离线统计知识画像生成，以及在线用户任务与实际数据画像生成。两条工作流可以共享字段规范，但必须分别保存来源、事实、推断和验证状态。

2.1 专业 Agent 及职责

Agent

职责与输出

Agent 1：多模态输入与任务理解

解析文本、表格、图片、图表、PDF；提取研究目标、分析任务、变量角色、期望输出与未知信息；输出任务画像。

Agent 2：数据结构与变量画像

调用 R/Python 计算样本量、变量数量、变量类型、缺失率、重复记录、取值范围、唯一值数量及描述统计；输出数据集级和变量级画像。

Agent 3：分布、质量与多元关系画像

按需分析偏态、异常值、缺失模式、相关性、协方差、共线性、矩阵秩、有效维度、分组及重复测量结构。

Agent 4：统计知识画像

从 R 官方文档、软件包手册、函数签名和示例中抽取用途、输入输出、参数约束、统计假设、适用条件和失败边界。

Agent 5：画像整合与质量验证

合并画像、检查字段完整性与冲突、核对证据、标记不确定性；必要时触发重新计算或人工复核。



实现原则：每个 Agent 都要有明确输入、输出、职责边界和调用条件。数值统计优先由程序计算；LLM 主要负责语义理解、文档抽取、复杂信息整合和解释。各 Agent 可以共用同一个模型服务。

2.2 两条画像工作流

离线知识画像：R 官方文档、软件包参考手册、函数帮助、函数签名和示例代码 → 文档解析与统计语义抽取 → 程序校验与证据审核 → 统计知识画像库。

在线数据画像：用户需求与数据文件 → 多模态解析 → 数据统计工具 → 统计语义解释 → 画像整合与质量验证 → 任务画像和实际数据画像。

四、必须落实的五项画像改进要求

提高画像粒度：不只使用“高维”“低维”“数值型”等粗粒度标签，应尽可能保存实际数值、变量级信息和数据结构。

提高统计语义准确性：区分实际观测分布、模型假设、残差诊断、数据事实和 LLM 推断。

增加多元结构信息：重点刻画相关性、协方差、共线性、矩阵秩、分组关系、重复测量及其他多元结构。

增加证据与不确定性：记录来源、计算方式、文档依据和验证状态；未经验证的推断不能作为确定事实。

让画像参与检索与方法选择：画像必须影响候选过滤、排序及不适用条件识别，而不只是生成描述性报告。

DARE 的公开方法作为重要参考基线。需要核实其公开画像字段、检索流程、代码与评估协议的可复现性；在对照实验完成前，不宣称新方案已经优于 DARE。

五、双编码器检索与统计约束惩罚

5.1 双编码器与余弦相似度

使用现成 Embedding 模型将用户任务画像与实际数据画像组合成查询表示，将 R 函数或统计方法知识画像编码为候选文档。查询与候选必须处于同一语义空间；如果使用两个独立编码器，必须先确认向量空间已对齐。

对查询向量和候选向量进行 L2 归一化：

q̂ = q / ||q||₂，     d̂ᵢ = dᵢ / ||dᵢ||₂

余弦相似度为：

sᵢ = q̂ᵀ d̂ᵢ

归一化后点积等于余弦相似度。对零向量、无效向量和空画像必须设置异常处理。查询应使用精炼的任务与画像摘要，而不是将完整数据文件或全部对话无差别地传入模型。

5.2 约束分层

类型

定义

处理方式

硬约束

明确不兼容，例如输入对象不支持或候选方法无法完成目标任务

排除候选，或要求先进行必要的数据转换

软约束

可能影响适用性、可靠性或计算可行性，但不一定意味着方法不可用

按严重程度施加惩罚，保留依据与解释

未知约束

尚未检查或证据不足，例如独立性或某项模型假设

标记未知；必要时触发诊断或请求补充信息，不直接判定满足或不满足



5.3 基线惩罚公式

Sᵢ = αsᵢ − λPᵢ

其中 sᵢ 为余弦相似度，Pᵢ 为软约束惩罚分数，α 为语义匹配权重，λ 为惩罚强度。

Pᵢ = Σⱼ wⱼ pᵢⱼ

pᵢⱼ 表示候选 i 在约束 j 上的不匹配程度，wⱼ 表示该约束的重要性。惩罚项需使用可比较的尺度，权重和阈值应通过验证集校准。未知约束不能直接赋予极大惩罚，应根据重要程度触发诊断或保留不确定性。

5.4 排序与结果解释

返回推荐函数/方法、初始余弦相似度、硬约束结果、各项软约束惩罚及其依据。

返回未知条件、必要诊断、最终排序分数、官方文档或画像证据、推荐理由与限制。

若所有候选均被硬约束排除，应输出可解释的失败结果，不得强行推荐。

5.5 后续扩展：BM25 混合检索

基线稳定后，可加入 BM25 关键词检索：Sᵢ = αsᵢ + βbᵢ − λPᵢ，其中 bᵢ 为经过适当归一化的 BM25 分数。不同检索分数不能未经校准就直接相加。Reranker 可作为后续可选模块，不属于第一阶段必要交付物。

十、执行原则与验收重点

请按照“先定义 Schema → 再实现画像生成 → 再实现检索与惩罚 → 最后打通执行闭环”的顺序推进。先提交架构设计、三类画像 Schema、五个画像 Agent 的职责与接口，以及最小可运行 Demo；通过确认后再扩大数据源规模。

核心验收问题

判断标准

画像是否可靠？

多 Agent 画像相较简单单 Agent 方案，是否在准确率、完整性、证据和统计语义上有可测量的改善

画像是否有用？

增强画像是否改善函数/方法检索与统计方法选择，而非仅增加描述性字段

惩罚机制是否有效？

是否降低不适用方法误推荐率，同时避免明显损害合理候选的召回率

系统是否可复现？

是否提供测试数据、配置、执行日志、评估脚本和可重复运行的结果



最终目标不是堆叠 Agent，而是证明：多 Agent 协作能够生成更可靠的数据画像，画像能改善统计方法匹配，统计约束惩罚能降低不适用方法的误推荐，并且整个系统可以稳定、可解释、可复现地运行。
